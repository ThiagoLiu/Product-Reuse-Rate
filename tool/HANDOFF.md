# 物料复用率工具 · 开发交接

项目当前版本为 **V1.0.0**，是 Windows 本地网页工具。源码基线为 GitHub `ThiagoLiu/Product-Reuse-Rate` 的 `main` 分支提交 `3b35d31`。后续开发先用 `git status --short --branch` 核对本地改动，并以当前源码为准。

## 运行与代码入口

| 文件 | 职责 |
| --- | --- |
| 根目录 `启动工具.cmd` | 在 `tool` 中启动当前源码。找到带运行环境的便携目录时，复用该目录的 Python 和数据库，否则用系统 Python。 |
| `app.py` | 本地 HTTP 服务、Excel 读取、统计、SQLite、回收站和迁移。 |
| `web/index.html`、`web/app.js`、`web/style.css` | 中文浏览器界面，无前端构建步骤。BYD Logo 随源码保存。 |
| `Launcher.cs`、`build_portable.py` | Windows 便携启动器和打包。 |
| `test_app.py`、`verify_portable.py` | 统计和持久化测试、实际交付 ZIP 的启动与接口验证。 |

在 `tool` 中安装 `requirements.txt` 后可运行 `python app.py`。调试时可用 `python app.py --no-browser --data-dir <独立测试目录>`，从终端读取本地网址。源码与旧 EXE 可能不同步，查看最新改动用根目录启动脚本。后台只监听回环地址。Windows 启动时会检查现有实例的源码版本，必要时关闭旧实例并启动新版。浏览器通过心跳维护页面状态，最后一个工具标签页正常关闭后通常约 6 秒退出，异常关闭时约 90 秒退出。

## 已确认的业务规则

- 每份 `.xlsx` 对应一个项目。遍历所有工作表，识别「子阶料号」「借用件/新开件」两列。每条有效物料行计一条记录，表中没有数量列。「借用件」即复用件。
- 同一编码出现在同一统计分类下至少两个不同项目中，跨项目重复编码种类数只加 1。仅出现在同一个项目的多个工作表或行中，不算跨项目重复。该重复编码的所有借用件行均从借用件计数排除。
- **复用率 =（跨项目重复编码种类数 + 排除重复编码后的借用件行数）÷（物料总记录行数 − 跨项目重复编码种类数）**。分母按公式减重复编码种类数。一个编码出现在三个以上项目时，分母仍只减 1。分母为零显示「暂无结果」。
- 最小分类使用现有公式，对该分类全部有效项目重新计算。同一编码跨小分类出现时，各小分类独立判断。无子分类的大分类可以直接存项目并计算。
- 首次添加小分类时，已有直属项目自动归入「未分组」，原表与历史版本随项目保留。项目可以在同一大分类下的小分类间移动。同名项目冲突由数据库约束拒绝。
- 有子分类的大分类使用有结果的小分类的算术平均，各小分类等权，`0%` 属于有效结果。总览可切换大分类平均值和最小分类复用率两种降序柱状图。

现有座椅样表的验收值为 42 条记录、2 种跨项目重复编码、22 条排除重复后的借用件记录，复用率为 **60%**。这两份业务样表在项目目录外的同级「座椅」目录，未进入 Git。

## 数据与兼容

- SQLite 保留项目明细、原始 Excel 副本、历史版本和回收站。删除外部原表不影响计算。相同项目更新只用最新版本参与计算。
- 源码默认使用 `tool/data/reuse.sqlite3`。启动脚本复用便携环境时，数据库位于实际选中的便携目录下的 `data/reuse.sqlite3`。现场可能存在多个便携目录，排查数据缺失时先确认实际启动路径。
- 数据库结构当前为版本 2，分类用 `parent_id` 表示两级关系。启动支持升级版本 1。迁移包包含数据库及校验清单，可恢复版本 1 或 2 的数据库，并在替换当前数据库前自动备份。
- 界面已删除计算记录、文件夹导入、退出按钮和统计导出入口。`snapshots` 表仍用于旧数据库兼容，报表接口仍可用于现有验证。项目、分类的删除和恢复需要继续考虑其对子分类和排名的影响。

## 开发验证与交付

1. 在 `tool` 中运行 `python -B -m unittest -v test_app.py`。缺少真实样表时对应测试会跳过，其余用临时数据库验证。
2. 前端改动可运行 `node --check web/app.js`。涉及界面交互时使用独立测试库在浏览器验证。
3. 需要交付时使用安装了依赖的 Windows 64 位 Python 3.14 运行 `python build_portable.py --output <暂存目录>/ProductReuseRate`。将该目录压成 ZIP，排除 `data`，然后运行 `python verify_portable.py --archive <交付ZIP>`。此验证需要本地座椅样表。
4. 交付用户的是完整便携 ZIP。需要历史数据时另发迁移包。GitHub 只提交源码、说明和测试，原始表格、数据库、备份和交付包留在本地。当前 GitHub 仓库为公开，发布前核对实际提交文件。
